Apply the TropOMI column averaging kernel when simulating observations.

The transform from `ModelOutputData` to `ObsData` previously computed a simulated
observation as the pressure-weighted mean of the CMAQ column between the model
surface and the model top. The column averaging kernel was read from the
retrieval and stored but never applied, the retrieval's a-priori profile made no
contribution, and the model was never mapped onto the retrieval's vertical grid.
The simulated column is now

    y = sum_j pw_j [ x_a,j + A_j ( x_m,j - x_a,j ) ]

following https://github.com/hannahnesser/TROPOMI_inversion, with the model
mapped onto the retrieval levels by pressure overlap. The operator is still
affine in the model state, so the adjoint forcing is unchanged; the part of the
column that does not depend on the model is carried in a new per-observation
`offset_term`.

CMAQ's top (VGTOP, 5000 Pa) sits well below the top of the retrieval grid, so
about 5% of the air mass is outside the model, all of it inside the topmost
retrieval layer. That part of the column is filled by assuming CMAQ has the
vertical structure right up to its top and the retrieval prior has the structure
but not the magnitude right above it: the prior profile is shifted by the
constant that makes it continuous with the CMAQ profile at the model top. The
two alternatives, trusting the prior outright and stretching the top model layer
to the top of the atmosphere, are available in
`openmethane.obs_preprocess.column_operator` and are covered by tests.

The retrieval prior is now converted to a dry-air mole fraction using the
retrieval's own `dry_air_subcolumns`, rather than a hydrostatic estimate that
ignored water vapour, and the retrieval level pressures are anchored on the
reported `surface_pressure`.

**Observation files must be regenerated.** `tropomi_methane_preprocess.py` now
stamps `obs_operator_version` into the domain metadata, replaces `alpha_scale`,
`ref_profile` and `model_pweight` with `offset_term`, `prior_profile`,
`sat_pressure_weight` and `model_coverage`, and writes different `weight_grid`
values. Files written before this change still load, with a warning and a zero
offset, but the observations they simulate will be wrong.

Simulated columns move by of order 10 ppb, comparable to the assumed observation
uncertainty, so cost function values and posterior emissions are not comparable
across this change.
