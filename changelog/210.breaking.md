Take the area to fetch TropOMI data for from the domain definition file named by
the `DOMAIN_FILE` environment variable, as `scripts/alerts/alerts_baseline.py`
already does, rather than from a bounding box in `config/obs_preprocess/`.

`config/obs_preprocess/config.json` and `config/obs_preprocess/config.austtest.json`
are removed, along with the `-c`/`--config-file` option of `fetch_tropomi.py` and
the `TROPOMI_FETCH_CONFIG_FILE` variable in `scripts/run-all.sh`. `DOMAIN_FILE`
must be set; the `docker-e2e-daily.sh` and `docker-e2e-monthly.sh` scripts already
set it, and it has been added to `.env.docker-test`.

The box is read from the `x_bounds` and `y_bounds` cell edges and converted to
longitude and latitude with `openmethane.util.domain.domain_bounding_box`, using
the projection the domain declares through its CF grid mapping variable. The
conversion samples along the projected edges, which curve in a geographic CRS,
rather than transforming the four corners.

`DOMAIN_FILE` is now listed in `docs/parameters.md`.

The derived boxes differ slightly from the ones they replace, which were
maintained by hand and did not quite match their domains. Both previously clipped
the southern edge: `aust10km` reaches -47.056 where the box stopped at -47.0, and
`au-test` reaches -23.780 where the box stopped at -23.5. Granules that only
clipped the southern edge of a domain could therefore have been missed.

Fetched granules now go directly into the output directory, keeping the filename
they have in the bucket, instead of into a subdirectory named after the period and
bounding box. Since the bucket serves whole granules, the name no longer describes
anything about the file, and the granule names are already unique.

Two consequences for anything reading those files:

- The extension is now `.nc` rather than `.nc4`, since the name is no longer
  rewritten. `scripts/run-all.sh`, `scripts/obs_preprocess/process_tropomi.sh` and
  `scripts/obs_preprocess/submit_tropomi_methane_preprocess.sh` have been updated;
  any other `--source` glob needs the same change.
- There is no longer a per-fetch subdirectory, so `--source` globs directly in the
  output directory. `scripts/run-all.sh` now writes to
  `${STORE_PATH}/tropomi/${START_DATE}`, matching what `fetch_tropomi.sh` and
  `process_tropomi.sh` already used.

The output directory is no longer emptied before a fetch, which would have meant
deleting the contents of a directory chosen by the caller. Granules already present
are skipped instead, so a rerun after a failure only fetches what is missing.
Stale granules from an earlier run with different dates are harmless, because
`tropomi_methane_preprocess.py` filters observations to `START_DATE` and
`END_DATE`, but they do cost time to read.
